! The Core Problem: How Do LLMs Represent Items?
Generative Recommendation replaces the traditional recall → rank pipeline with an LLM that autoregressively generates item identifiers from user behavior. The critical question: how to represent items so an LLM can reliably generate them?

★ Solution: Term IDs (TIDs) — Best of Both Worlds
Term ID = a fixed-length sequence of semantic keywords from the LLM's own vocabulary.
Each product is compressed into structured keyword slots ordered by importance.

Example: "Blue Mountain Unisex PVC Rainsuit"
→ TID: [rainsuit, waterproof, pvc, unisex, mountain, blue, outdoor]

Why it works:
▸ Native vocabulary — no vocab expansion or alignment training needed
▸ Compact — 5~7 tokens per item vs. 20+ token titles → efficient sequence modeling
▸ Semantic — human-readable, captures core features, enables cross-domain transfer
▸ Low hallucination — GRLM achieves >99% valid rate (VR@10) and >99% direct hit rate
⚙ Context-Aware Term Generation (CTG)
Problem: Naive LLM extraction produces inconsistent terms — "Cell-Phone" vs. "Mobile-Phone" for similar items, or identical generic terms for different models.

Solution: Inject neighbor context so the LLM sees similar items when generating:

⚡ ShoppingGenRec: From Next-Item to Shopping Journeys
GRLM predicts one next item from a user behavior sequence. But real shopping surfaces need themed multi-product journey generation — coherent groups of recommendations with titles, reasons, and diverse products. ShoppingGenRec extends GRLM to this new paradigm.
Adaptation 1  TermID: 5 Slots → 7 Slots
Production shopping catalogs (apparel, electronics, home) have richer attribute spaces than academic datasets. 7 slots with priority category → function → feature → attribute → brand → seller → audience reduce collision while the paper confirms 7-slot performance ≈ 5-slot (no degradation). Non-product items (services, software, restricted) filtered via empty [] output.
T Multi-Task SFT Design — 3 Tasks
Task 1  Meta → TermID (Generative Term Internalization)
Product metadata → 7-word TID. Teaches model to internalize the TermID mapping without neighbor context (same as GRLM's GTI). Foundation for generating valid identifiers at inference time.
Task 2  Events → Journeys (NEW: replaces next-item prediction)
User event history (browse/click/search + timestamps) → structured JSON: N themed journeys × M product TIDs. Each journey has title, personalized reason, and diverse product recommendations. Diversity algorithm: hard dedup (≥6/7 word overlap) + greedy reranking (minimize max overlap) + brand/seller tie-breaking.
Task 3  Profile + Events → Journeys (NEW: cold-start mitigation)
LLM-generated 11-field user profile (gender, categories, brands, price sensitivity, fashion style, values, etc.) + events → journeys. Richer personalization for sparse-event users.

R TID → Product Resolution (Elastic Identifier Grounding)
Model outputs TermIDs, not product IDs. GRLM introduced Elastic Identifier Grounding (EIG) — we extend it for shopping journeys:
Exact Match → Normalized (case/space) → Sorted (order-invariant) → Fuzzy Prefix (position-weighted: wj=1/(j+1))
Dedup by product ID and journey title. Enables soft matching even with word-order variations.
R RL Alignment (GRPO) — Zero Data Leakage Design
3-way split from journey product sequence [item₁ ... itemN-2 | itemN-1 | itemN]:
▸ RL Prompt: instruction + events + output up to itemN-2
▸ Reward Signal: itemN-1 TermID (for GRPO reward computation)
▸ Held-Out Test: itemN TermID (never seen during training)
Strict isolation via EasyR1/verl format. Prevents reward hacking.
! Known Issues
  • TID Collision: ~2-3% items share identical 7-word TIDs (color/size variants). Grows with catalog scale
  • LLM Validity: Not all items get exactly 7 valid words — partial outputs need fallback
  • Teacher Bias: Training journeys are LLM-generated, not human-curated
  • Profile Cold-Start: Sparse-event users get generic profiles
  • Eval Cost: Journey quality (0-2 UHRS scoring) requires human evaluation
  • Diversity-Relevance: Aggressive diversity reranking may push out highly relevant similar products
→ Next Steps
  • RL Training: Run GRPO with verl/EasyR1 to align with journey quality rewards
  • Collaborative Signals: Add co-purchase/co-view patterns (GRLM's SASRec task)
  • Adaptive TID Length: Dynamic 5-9 slots by catalog complexity
  • Online A/B: Deploy to production, measure CTR/conversion/journey completion
  • Multi-Market: Multilingual TIDs, cross-market catalogs
  • LLM-as-Judge: Replace human UHRS with automated eval for faster iteration
